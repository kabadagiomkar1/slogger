# Domain docs

Layout: single-context.

## Before exploration

Read the root `GLOSSARY.md` and relevant decisions in `docs/adr/`
when they exist. Proceed silently when they do not exist.
Create them as terms and decisions are resolved.

## Consumer rules

- Use the glossary's terms in specs, tickets, tests, and designs.
- Surface conflicts with existing ADRs explicitly.
- Record genuine vocabulary gaps for domain modeling.
